## 1. VISION & EMOTIONAL DESIGN LANGUAGE

### What this app IS
- A gift from a boyfriend to his girlfriend
- A comfort space she opens when she feels low
- A period + mood tracker that feels like a warm hug
- A capsule of his love — messages, voice notes, memories
- A self-care ritual, not a medical dashboard

### Design Inspiration Reference
The uploaded reference image (MY PITA app) shows the correct aesthetic direction:
- Soft pink/blush color palette — NOT bubblegum, but warm dusty rose
- Illustrated character (anime/kawaii style girl)
- Rounded cards with soft shadows
- Clean white surfaces with pink accents
- Friendly, not clinical
- Feature cards with illustrations
- Data shown warmly (not as cold numbers)

### Emotional Design Principles
Every screen must follow these rules:
1. **Warm first** — colors, copy, and layout should feel like a hug
2. **Personal always** — use her name everywhere, frequently
3. **Never empty** — every empty state has a message from him or a soft illustration
4. **Animate with care** — transitions should feel like breathing, not snapping
5. **Data feels gentle** — show numbers inside warm card contexts, never as raw lists
6. **His presence is felt** — subtle reminders that he built this for her

## 2. TECH STACK

```
Frontend:        Flutter 3.x (latest stable)
State Mgmt:      Riverpod 2.x (riverpod_annotation + code gen)
Navigation:      GoRouter 13.x
Backend:         Firebase (Firestore, Auth, Storage, FCM, Remote Config)
Local Storage:   Hive + flutter_secure_storage
ORM/Local DB:    Drift (for complex cycle data queries)
Animations:      flutter_animate, rive (for character animations), lottie
HTTP:            Dio (for any 3rd party APIs)
AI:              Anthropic Claude API (claude-sonnet-4-20250514) via http
Push:            Firebase Cloud Messaging
Images:          cached_network_image, image_picker
Audio:           just_audio, record
Encryption:      encrypt (AES for journal)
DI:              Riverpod (no get_it needed)
Code Gen:        build_runner, riverpod_generator, freezed, json_serializable
Testing:         flutter_test, mocktail, riverpod testing utils
```

### Firestore Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Users can only read/write their own data
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }

    // "From him" messages: partner writes, user reads
    match /fromHim/{userId}/{document=**} {
      // User can read their own "from him" content
      allow read: if request.auth != null && request.auth.uid == userId;
      // Partner (identified by partnerUid) can write
      allow write: if request.auth != null
        && exists(/databases/$(database)/documents/users/$(userId))
        && get(/databases/$(database)/documents/users/$(userId)).data.partnerUid == request.auth.uid;
    }
  }
}
```

## 15. DO'S AND DON'TS

### DO ✅
- Use `const` constructors everywhere possible
- Handle all `AsyncValue` states: data, loading, error — always
- Use `ref.listen()` for side effects, `ref.watch()` for UI
- Use `Freezed` for all data models
- Use `Result<T>` for repository return types — never throw across layers
- Use `GoRouter` named routes (define route name constants in `app_routes.dart`)
- Add haptic feedback on all primary actions (`HapticFeedback.lightImpact()`)
- Test `CycleCalculator` logic thoroughly — it's the core algorithm
- Cache network images with `CachedNetworkImage`
- Use `flutter_animate` for UI animations — not raw `AnimationController` unless custom
- Use `const` for all `TextStyle`, `BoxDecoration` where possible
- Add loading shimmer on all screens that fetch data
- Implement offline-first: Drift local → sync to Firestore
- Use `flutter_secure_storage` for PIN and encryption key
- Keep the Cormorant Garamond font for all emotional/display text

### DON'T ❌
- Don't use `GetX` or `Provider` — only Riverpod
- Don't call `ref.read()` inside `build()` — use `ref.watch()` in build
- Don't store encryption keys in Firestore or Hive
- Don't use `Navigator.push()` — use GoRouter's `context.go()` / `context.push()`
- Don't put business logic in widgets — use Notifiers/Repositories
- Don't use excessive pink (#FF69B4 style) — use the warm dusty rose palette defined above
- Don't show empty white screens — always have an empty state widget
- Don't use `FutureBuilder` or `StreamBuilder` — use Riverpod's AsyncValue
- Don't ignore errors — always show a gentle, warm error state
- Don't use generic fonts (Inter, Roboto) — use the specified type system
- Don't skip haptic feedback on meaningful interactions
- Don't show cold/clinical data displays — always wrap numbers in warm card contexts
- Don't use bottom nav labels only — include icons + optional labels
